## 6. 점검 방법과 재현

### 6.1 검색 및 중복 제거

검색어 24개는 [검색 기록](../audit/retired-site-search-log.md)에 남겼다. 브랜드명과 종료·연도·채용·이벤트 표현, 공식 도메인 제한을 조합했다. 검색 결과에서 직접 URL과 공고에 실린 링크를 추출했다. 이벤트 번호·경로·서브도메인을 추측하거나 확장하지 않았다. 대학 미러·URL의 페이지 이동 파라미터는 별도 독립 시스템으로 세지 않는다. 검색엔진에서 결과가 안 나온 사실을 사이트 부재로 판정하지 않는다.

### 6.2 공개 응답 수집

고정 목록 C01~C05만 대상으로 각 일반 GET 1회, 요청 사이 최소 1.5초, 요청당 10초, 본문당 1 MiB 제한을 사용했다. 인증정보를 보내지 않고 리다이렉트·참조 JS/CSS·폼을 따라가지 않았다. DNS 실패는 응답 실패로 기록했다. HTTP 비200에서는 본문 수집/재시도를 하지 않았다. TLS 검증을 비활성화하지 않았다.

```powershell
# 실제 외부 요청을 최대 5회 다시 발생시킴. 오프라인 명령이 아님.
node audit/collect-retired-candidates.mjs
```

요청 시각·URL·상태·선별 헤더·본문 SHA-256을 JSON으로, 성공한 본문을 HTML로 보관했다. 쿠키 원문은 결과 JSON에 저장하지 않았다. 외부 서버 로그는 접근하지 못했으며 요청 흔적을 삭제/은폐하지 않았다. 웹 검색/열기 도구의 요청은 위 수집 스크립트 5회와 별개이고 그 도구의 총 네트워크 요청 수는 확인할 수 없다.

### 6.3 정적 검사

CSP·Report-Only·X-Frame-Options·HSTS·nosniff·캐시·검색 로봇 헤더를 확인했다. HTML에서 CSP/robots meta, script src, 폼/입력 태그를 추출했다. 이는 정규식 기반 UTF-8 텍스트 검사이며 브라우저 DOM 파서·렌더링·JS 실행을 대체하지 않는다. robots meta 미검출은 robots.txt가 없다는 뜻이 아니다. robots.txt는 요청하지 않았다.

### 6.4 운영 종료 확인 방법 — 담당자 후속 절차

마케팅/인사 소유자 확인 → 공고/캠페인 종료일 확정 → 웹·API·DB·SMS/경품·분석 연동 목록 대조 → 보존/폐쇄 결정 → 변경 승인 → 테스트 환경 검증 → 운영 반영 후 재점검 순서로 진행한다. 화면에서 신청 버튼을 숨기는 것만으로 접수 종료를 완료 처리하지 않는다.

### 6.5 추가 취약점 검증 방법 — 이번 미수행

| 검사 | 필요한 자료 | 테스트 환경 합격 기준 |

## 7. 폐쇄와 검색 제외 방법

완전 폐쇄라면 필요한 자료 보존 후 기능·연동·계정/키를 정리하고 해당 자원에 404/410을 반환한다. 동등한 후속 페이지가 있으면 적절한 리다이렉트를 검토한다. 공개 아카이브를 유지하면서 검색에서만 제외하려면 noindex를 사용하되 검색로봇이 해당 지시를 읽을 수 있어야 한다. 민감 자료는 접근통제로 보호한다. **noindex와 robots.txt는 보안 접근통제가 아니다.** [Google 삭제 지침](https://developers.google.com/search/docs/crawling-indexing/remove-information), [Google 404/410 안내](https://support.google.com/webmasters/answer/2445990?hl=en)

네이버 서치어드바이저와 Google Search Console에서 소유자 권한으로 검색 제외·갱신을 요청한다. 외부 대학/채용 사이트의 본문 링크도 정정한다. 검색 제외는 서버 폐쇄나 취약점 수정을 대신하지 않으며 즉각 반영을 보장하지 않는다. [네이버 검색 제외](https://searchadvisor.naver.com/guide/faq-serpremove), [네이버 수집·검색 제외 절차](https://searchadvisor.naver.com/guide/request-crawl)
