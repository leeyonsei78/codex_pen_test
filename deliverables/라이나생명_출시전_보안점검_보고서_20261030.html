# 라이나생명 주소 목록 출시 전 공개 영역 재점검

공개 응답에서 보안 설정 결함과 테스트 페이지 공개를 확인했다. 인증 우회·계정 탈취·서버 침입은 확인하지 않았다. 실제 애플리케이션 소스·설정·테스트 계정·로컬 서비스가 제공되지 않아 원본 수정과 인증 기능 검증은 미완료이며, 출시 가능 판정은 보류한다.

범위와 수행 방법

원문 DOCX의 HTTPS URL 31개와 8개 호스트의 HTTP 루트 주소를 점검했다. Node.js 기본 인증서 검증을 유지한 HEAD 39회와 목록 내 HTML 7개에 대한 GET 7회를 순차 수행했다. 요청 간격은 HEAD 최소 1초, GET 최소 1.5초였다. GET 본문은 건당 1 MiB, 시간은 10초로 제한했다. 리디렉션·연결 스크립트·설치 파일은 따라가지 않았다. 쿠키 값은 저장하지 않았으며 받은 쿠키를 후속 요청에 재전송하지 않았다.

로그인·인증·토큰 발급·API 실행·폼 제출·다른 계정 접근·주문·결제·부하 시험·데이터 변경은 수행하지 않았다. HTML의 JavaScript는 실행하지 않고 정적으로 검토했다. 서비스 중단 여부는 사용자 설명과 별도로 검증되지 않았으며, 외부 공개 주소로 취급했다. HTTP 200은 업무 기능 작동이나 서비스 운영 여부를 보증하지 않는다.

실제 애플리케이션 파일 대신 작업 폴더의 기존 audit/ 점검 산출물만 확인했다. 과거 보고서의 결론은 이번 실시간 검증 결과와 섞지 않았다. 최초 curl 점검의 로컬 Schannel 오류는 이번 Node.js 수집으로 상당 부분 해소됐다. 최초 보고서는 보존하며 현행 판단은 이 재점검을 따른다.

관찰 결과

HTTPS 31개 중 30개가 200을 반환했다. blog.lina.co.kr은 ERR_SSL_TLSV1_ALERT_INTERNAL_ERROR로 실패했다. 인증서 검증 우회나 반복 시도는 하지 않았다. TLS 실패 원인이 서버·중간 장비·접속 환경 중 무엇인지는 미확인이다. TLS 버전·암호군 전체 점검은 수행하지 않았다.

HTTP 8개 중 www, m, ga, direct, mdirect, blog.direct는 동일 호스트 HTTPS 루트로 301 또는 302를 반환했다. srm, blog는 403을 반환했다. 403을 평문 콘텐츠나 로그인 정보 노출로 분류하지 않았다.

발견 사항

아래 우선순위는 수정 검토 순서이며 원격 공격 성공 또는 CVSS 점수가 아니다. HEAD와 GET 차이를 보존하며, GET하지 않은 주소의 본문·실행 동작은 미확인이다.

R01 GA SSO 연동 테스트 페이지 외부 공개

근거: get-public-review/page_9.html 및 같은 폴더 results.json의 id 9. 비인증 GET이 200을 반환했다. HTML 90~91행에는 테스트용으로 화면 초기화 검사를 비활성화한다는 주석과 gfnInitGP 호출 주석 처리가 있다. 103~116행에는 입력 사번·고객사코드로 요청 파라미터를 구성하는 코드, 137~140행에는 반환된 tokenKey를 모달에 표시하는 코드가 있다. 본문 SHA-256은 증적 JSON에 기록했다.

판정 및 영향: 테스트 화면과 클라이언트 구현 공개는 확인. 서버 측 인증·권한 검증 부재, 타인 사번 사용, 실제 토큰 발급·탈취는 미확인이다. 서버가 클라이언트 입력을 신뢰할 경우 권한 오용으로 이어질 수 있다는 조건부 위험이다. 우선순위 높음, 실제 취약점 심각도 미정.

수정: 출시 산출물에서 테스트 HTML 및 연관 테스트 기능을 제거하고 ingress에서도 해당 경로를 제한한다. 클라이언트 검사 복원만으로 해결하지 않는다. SSO 발급 서버는 사용자 식별자를 인증된 서버 세션에서 결정하고 고객사 권한·토큰 수신 대상·만료·재사용 방지를 검증한다. 토큰의 화면 출력과 로그 기록은 제거한다.

검증: 공개 파일과 코드만 확인했으며 발급 요청은 하지 않았다. release-policy.example.mjs는 해당 테스트 페이지의 대표 경로를 차단하는 참고 코드다. 로컬 HTTP 테스트에서 쿼리·대소문자·후행 슬래시 변형이 애플리케이션으로 전달되지 않는 것을 확인했다. 인코딩·별칭·다른 테스트 경로 전체를 포괄하는 보안 경계는 아니며, 원본 제거와 서버 검증을 대신하지 않는다. 실제 적용 및 발급 서버 회귀 검증은 미완료다.

R02 프레임 제한 및 CSP 방어 미흡

근거: GET id 1의 홈페이지에는 CSP·X-Frame-Options가 없다. GET id 3, 9, 14, 15, 22의 GA 페이지는 script-src * 'self' blob: 'unsafe-inline' 'unsafe-eval'를 반환했고 frame-ancestors·X-Frame-Options가 없다. 전자구매 GET id 16에는 SAMEORIGIN이 있어 같은 결함으로 분류하지 않았다.

판정 및 영향: 관찰 응답의 방어 설정 미흡 확인. GA는 외부 스크립트 출처·인라인 코드·문자열 코드 실행 허용 범위가 넓다. 이를 단독 XSS나 클릭재킹 성공으로 판정하지 않는다. 브라우저 프레임 삽입, 쿠키 조건, 민감 동작 실행은 미확인이다. 우선순위 중간.

수정: 허용할 프레임 부모를 확인한 뒤 응답 헤더에 frame-ancestors 'self' 또는 승인된 출처 목록을 적용한다. 스크립트 출처는 실제 필요한 출처로 제한하고 인라인 코드의 nonce/hash 전환 및 eval 의존성 제거를 테스트 환경에서 진행한다. 전체 CSP를 즉시 강제해 로그인·전자서명을 중단시키지 말고 Report-Only로 호환성을 먼저 검토한다. 프레임 정책 강제는 별도로 검증한다.

검증: 참고 미들웨어의 로컬 테스트에서 정상·404 응답의 프레임 정책 적용과 기존 script-src 보존을 확인했다. 참고 코드는 완전한 스크립트 CSP나 nonce 구현이 아니다. 원격 서비스는 변경하지 않았다. 정책 해석 근거는 W3C CSP 명세이다.

R03 전자구매 세션 쿠키 속성 중복 및 응답별 차이

근거: HEAD id 4, 16, 27의 JSESSIONID에는 Secure, HttpOnly가 반복되고 SameSite=Lax, SameSite=None이 동시에 포함됐다. GET id 16에서는 Secure·HttpOnly 중복과 SameSite=None이 관찰됐으며 Lax는 없었다. 쿠키 값은 수집 증적에서 제외했다.

판정 및 영향: 중복 및 정책 불일치 확인. SameSite=None은 교차 사이트 흐름을 위해 의도했을 수 있다. 세션 탈취나 CSRF 성공은 확인하지 않았다. 인증 전 접근 제한 화면이 발행한 쿠키이며 로그인 후 세션 속성은 미확인이다. 우선순위 중간.

수정: 애플리케이션과 프록시 중 쿠키 속성을 설정하는 계층을 정리해 각 속성이 한 번만 나오도록 한다. Lax/Strict/None은 SSO 요구에 따라 하나를 선택하고 Secure·HttpOnly를 유지한다. None이 필요하면 상태 변경 요청에 별도 CSRF 토큰과 Origin 검증을 적용한다.

검증: sessionCookieOptions 참고 함수의 로컬 테스트에서 Secure·HttpOnly 강제와 단일 SameSite 선택, 잘못된 설정 거부를 확인했다. Java 세션 설정과 프록시 원본이 없어 실서비스 패치는 작성하지 못했다. 쿠키 발행 원칙의 근거는 RFC 6265 4.1.1이다. 이 RFC 자체를 SameSite 세부 동작의 근거로 사용하지 않는다.

R04 공개 런타임 설정에 내부 서비스 주소 포함

근거: GET id 1의 page_1.html 런타임 설정에는 VUE_APP_PRIVATE_COMMON_API_DOMAIN, PRIVATE_DOMAINS와 Kubernetes 형식의 내부 서비스 HTTP 주소가 포함된다. 전체 값은 증적에 남기되 이 보고서에서 반복하지 않는다.

판정 및 영향: 내부 구성 정보 공개 확인. SSRF, 내부망 접속 또는 비밀키 유출을 입증한 것은 아니다. 우선순위 낮음.

수정: 내부 API 주소는 서버 전용 환경 변수·설정으로 옮기고 클라이언트 직렬화 대상에서 제외한다. 공개 클라이언트 식별자를 비밀키로 오인하지 말고 실제 자격 증명 여부를 별도 분류한다.

검증: 공개 HTML에서만 확인했다. SSRF·내부 주소 접속은 하지 않았다. Nuxt 원본 설정이 없어 삭제 패치와 빌드 검증은 미완료다. 수정 후 배포 HTML과 브라우저용 번들에 내부 주소·서버 전용 키가 없는지 확인한다.

R05 블로그 nosniff 헤더 부재 및 연결 실패

근거: HEAD id 8의 blog.direct.lina.co.kr 응답에는 X-Content-Type-Options가 없다. id 7의 blog.lina.co.kr은 TLS 연결 실패다.

판정 및 영향: 첫 항목은 HEAD 관찰에 한정한 방어 설정 미흡, 두 번째는 접속 문제로 미확인이다. 콘텐츠 스니핑 공격이나 인증서 결함으로 확정하지 않는다. 우선순위 낮음.

수정 및 검증: 올바른 Content-Type을 먼저 확인하고 nosniff를 적용한 뒤 정상 GET·정적 리소스를 검증한다. TLS 오류는 승인된 다른 접속 위치와 서버·인증서·중간 장비 로그로 확인한다. 이번에는 블로그 본문·업로드 기능·지원 암호군을 확인하지 못했다.

수정 예시와 검증 범위

release-policy.example.mjs와 release-policy.test.mjs는 이번 점검을 위해 작성한 독립 참고 코드다. 실제 스택은 Nuxt·Java 및 프록시가 혼재한 것으로 보이므로 그대로 배포하지 않는다. 원본 파일은 변경하지 않았고 서비스에 배포하지 않았다. 로컬 회귀 테스트 2개가 통과했다. 이는 참고 코드에 대한 검증이며 실제 사이트 수정 완료를 뜻하지 않는다.

실행: node --test lina_header_review_20261030/release-policy.test.mjs

새 온라인 수집 스크립트는 증적 폴더가 이미 있으면 중지하므로 기존 수집을 덮어쓰지 않는다. HEAD와 GET 결과 JSON에는 시각·URL·헤더·마스킹한 쿠키 속성이 있고, GET에는 본문 크기·SHA-256·저장 파일명이 있다.

출시 전 조치

  1. 테스트 화면의 배포 제외와 서버 측 SSO 권한검증을 우선 확인한다.
  2. 프레임·CSP·세션 쿠키 정책을 테스트 환경에서 조정하고 로그인·전자서명·허용된 SSO 흐름의 회귀를 확인한다.
  3. 서버 전용 설정의 클라이언트 공개를 제거하고 블로그 TLS 및 헤더를 재검증한다.
  4. 실제 소스·배포 설정·테스트 계정이 제공되면 위 미확인 항목을 검증하고 실제 패치와 변경별 회귀 테스트를 작성한다.
  5. 운영 적용·정책 변경·실제 기능 검증은 검토할 변경안과 영향 범위를 먼저 공유한다.

수정 참고 코드와 테스트

아래 코드는 실제 애플리케이션에 적용하지 않은 통합 참고 예시입니다. 원본 소스와 배포 스택을 확인한 뒤 적용 방법을 결정해야 합니다.

정책 참고 코드

// Integration reference only. Not installed in the actual application.
// Requires an HTTPS-only application behind a correctly configured TLS proxy.
export function sessionCookieOptions(sameSite = 'Lax') {
  if (!['Lax', 'Strict', 'None'].includes(sameSite)) throw new TypeError('Invalid SameSite');
  return { secure: true, httpOnly: true, sameSite, path: '/' };
}
export function releasePolicy(req, res, next) {
  // Apply at the trusted ingress as well, before application routing.
  const path = new URL(req.url, 'https://local.invalid').pathname;
  if (/^\/html\/gap\/GM\/GPN999M0\.html\/?$/i.test(path)) {
    res.statusCode = 404;
    res.setHeader('Cache-Control', 'no-store');
    res.end('Not found');
    return;
  }
  // Append to preserve any existing enforced script policy.
  // Confirm legitimate cross-origin embedding needs before enabling.
  res.appendHeader('Content-Security-Policy', "frame-ancestors 'self'");
  res.setHeader('X-Frame-Options', 'SAMEORIGIN');
  res.setHeader('X-Content-Type-Options', 'nosniff');
  next();
}
