### F03 정상 및 오류 응답의 프레임 제한

- 대상·조건: 이전 11월 1일 HTTPS 200 HTML 24개 저장 응답, 로컬 미들웨어. 원격 오류 페이지 조회 없음.
- 근거: 이번 `summary.json` headerChecks: 22개는 X-Frame-Options 및 CSP frame-ancestors 모두 없음, SRM 2개에는 SAMEORIGIN 있음. 원격 401·403·404·500 및 게이트웨이 자체 오류는 이 집계로 판단할 수 없다.
- 관측·영향: 저장 응답에 헤더 기반 프레임 제한이 없다. 민감 동작 클릭재킹이나 실제 iframe 삽입 성공은 미확인이다.
- 추가 발견: 기존 참고 `audit/fixes/security-headers.cjs`는 기존 X-Frame-Options가 DENY여도 SAMEORIGIN으로 바꾼다. 기존 정책을 완화할 수 있는 **로컬 참고 코드의 결함**이며 운영 적용 사실은 없다. 기존 32건에는 DENY 보존 사례가 없어 탐지되지 않았다.
- 수정: 원본을 보존하고 [security-headers-preserve.cjs](../audit/followup-20261101-01/security-headers-preserve.cjs)를 새 예제로 작성했다. DENY를 유지하고 CSP에는 frame-ancestors 'none'을 추가한다. 기존 CSP를 보존한다. 정상 경로와 오류 경로 전에 실행해야 하며 CDN/WAF가 직접 만든 응답은 별도 설정이 필요하다.
- 상태: 원격 저장 응답의 헤더 기준 **FAIL**. 기존 예제의 DENY 보존 기준 **FAIL→새 예제 PASS(로컬)**. 새 예제 200·401·403·404·500 및 기존 CSP 보존 검사 7건 **PASS**. 실제 서비스·브라우저·배포 검증 **BLOCKED**.
- 완료 기준·잔여 위험: 최종 CDN 경유 정상·오류 응답, 허용·비허용 부모의 브라우저 결과, 정상 제휴 인증을 함께 검증한다. 새 예제는 통합되지 않았으며 모든 기존 정책 형식·애플리케이션 프레임워크를 검증한 범용 패치가 아니다. 담당: 프런트·인프라·QA.

### F04 CSP 허용 출처 및 축소 가능성

- 대상·조건: 이전 11월 1일 GA·SRM 저장 헤더의 지시문 목록 분석. CSP 브라우저 파서·온라인 위반 수집 없음.
- 근거: `responses.json` GA R03/R09 등, SRM R16/R27 및 이번 `static-review.json` csp.
- 관측·영향: GA는 script-src에 `*`, blob:, unsafe-inline, unsafe-eval을 허용한다. 자체 주입 결함이 있을 때 완화 효과가 제한될 수 있다. 이것만으로 XSS는 확정할 수 없다.
- SRM 추가 관찰: 결합된 두 정책처럼 보이는 쉼표 구분이 있고, script-src 및 script-src-elem에 self, data:, blob:, 인라인 허용과 외부 FileReader·FileSaver·Ace·lodash·jsonpath 주소가 있다. 다른 정책에는 로컬 인증 프로그램으로 보이는 루프백 출처가 있다. 여러 정책은 함께 제한할 수 있으므로 첫 정책 허용만 보고 외부 실행이 가능하다고 단정하지 않는다. 헤더에 적힌 라이브러리를 실제 다운로드·실행했다는 뜻도 아니다.
- 상태: 스크립트 출처 최소화 목표에 대한 GA 저장 정책 **FAIL**. 각 허용 항목의 업무 필요성·실제 적용·안전한 축소 범위 **BLOCKED**.
- 수정·완료 기준: 개발·인증 연동 담당자가 각 출처/지시문별 호출자·페이지·소유자·필요성을 표로 확정한다. 테스트 환경에서 불필요 출처 제거, nonce/hash 및 Report-Only 평가 후 강제 정책으로 전환한다. 현재 자료로 unsafe-eval·루프백 허용을 즉시 제거할 근거는 부족하다. 실제 업무 회귀와 브라우저 CSP 결과가 완료 조건이다. 담당: GA/SRM 개발·인증 연동·인프라.

### F05 공식 블로그 TLS 원인 구분

- 대상·조건: `audit/recheck-20261101/responses.json` R07의 2026-11-01 13:43 KST 무렵 오류 기록만 분석. 이번 TLS 연결 없음.
- 관측: `ERR_SSL_TLSV1_ALERT_INTERNAL_ERROR`는 TLS 협상 중 오류 기록이다. 이름의 TLSV1만으로 TLS 1.0 사용을 뜻하지 않는다. 인증서 체인·SAN·발급자·만료·호스트명 검증 결과·협상 프로토콜이 수집되지 않았다.
- 상태: 인증서·체인·호스트명 원인 분리 **BLOCKED**. 이번 온라인 재접속은 **NOT_RUN**. 인증서 불량·서버 폐쇄·취약 TLS로 FAIL 처리하지 않는다.
- 수정·완료 기준: 인증서 담당자가 공개 leaf·intermediate 체인과 SAN·유효기간, SNI 가상호스트·TLS 로그를 제공한다. 네트워크 담당자는 점검 위치·프록시/TLS 중계·DNS 경로와 실패 시각 로그를 대조한다. 승인 후 인증서 검증을 유지한 정상 연결을 두 점검 위치에서 비교한다. 원인에 따라 체인·SNI·중계 설정을 수정하고 같은 조건에서 신뢰·호스트명 검증 성공을 확인한다. 개인키는 필요 없다. 잔여 위험은 가용성·신뢰 상태 미확인이다.

- 대상·조건: 10월 28일 저장 공통 요청 구문과 Axios URL 조합 함수, 예약된 .invalid 주소·합성 자격정보만 사용. 브라우저 전송 없음.
- 근거: `audit/path-evidence/common/P03.js` 오프셋 427, 이번 `verify-api-destination.mjs.json` 5건. 원래 요청 로직은 경로 문자열에 /api/ 또는 /public/이 포함되면 인증 헤더를 붙이는 조건을 가진다.
- 관측·영향: 외부 절대 URL 및 // 형태의 외부 URL에서도 해당 문자열이 있으면 합성 인증 헤더가 요청 설정에 남는 2건을 재현했다. 실제 호출자가 외부 URL을 제어하는지, 브라우저 preflight가 허용되는지, 네트워크로 전달되는지는 미확인이다.
- 상태: 저장 클라이언트의 목적지 제한 기준 **FAIL**. 기존 허용 출처 guard 예제 회귀 **PASS(로컬)**. 실제 유출·서비스 통합 **BLOCKED**.
- 수정·완료 기준: 토큰 부착 전에 HTTPS 정규화 URL의 정확한 origin을 검증하고, 요청 훅 이후 URL 변경·리디렉션 정책도 확인한다. `audit/fixes/approved-api-url.mjs`는 참고 함수이며 클라이언트 실제 연결을 증명하지 않는다. 정상 API 성공과 비승인 목적지 부착/전송 차단을 승인 테스트 환경에서 확인한다. 담당: 프런트 API 공통 모듈·QA.

### F07 토큰 저장 및 회전 계약

- 대상·조건: 저장 로그인·오류 처리 구문을 합성 데이터로 실행. 실제 토큰 값은 사용·출력·기록하지 않았다. 새 결과에서는 합성 자격정보 값도 마스킹했다.
- 근거: 이번 `verify-additional.mjs.json`, `verify-intrusion-paths.mjs.json`; `audit/path-evidence/common/P03.js` 오프셋 4731의 refresh 응답 값 대입 구문.
- 관측·영향: JS 접근 가능한 저장소/쿠키 대입 경로와, 합성 서버의 새 refresh 값이 이전 값으로 덮이는 동작을 재현했다. 전자는 XSS·스크립트 신뢰 문제와 결합될 때 영향이 있을 수 있고, 후자는 회전하는 서버와 계약이 다르면 재로그인 또는 보안 동작 불일치를 유발할 수 있다. 서버가 실제 회전하는지와 폐기·재사용 거부는 미확인이다.
- 상태: 구문 동작 재현 **PASS(로컬)**. 서버 세션 안전성 및 실제 쿠키 동작 **BLOCKED**. 현재 근거만으로 회전 우회·세션 탈취를 FAIL로 확정하지 않는다.
- 수정·완료 기준: 인증 담당자가 수명·회전·동시 요청·로그아웃 폐기 계약을 명시하고 클라이언트와 일치시킨다. JS 접근 최소화 방식은 아키텍처·CSRF 방어와 함께 검토한다. 승인 환경에서 새 값 저장, 이전 refresh 재사용 거부, 정상 갱신·로그아웃·만료를 통합 검증한다. 잔여 위험: 서버 통제 미확인. 담당: 인증 서버·프런트.

## 출시 차단 후보

1. **필수 서버 통제의 미검증**: A01~A08과 실제 수정 통합 검증이 끝나지 않았다. 확인된 인증 우회라는 뜻은 아니지만 출시 승인 근거가 부족하다. 인증/API 책임자와 QA가 승인 환경의 실제 결과를 제출해야 한다.
2. **HTML 메시지 경로와 목적지 제한**: F02/F06의 저장 클라이언트 동작을 재현했다. 입력 통제와 호출자 분석 또는 실제 원본 수정·통합 검증 전까지 우선 차단 후보로 관리한다. 악용 성공으로 분류하지 않는다.
3. **구버전 및 보안 헤더/CSP**: F01/F03/F04는 실제 반영 증거가 없다. 업무상 예외가 필요하면 허용 범위·보완 통제·담당 승인과 재검증 결과가 있어야 한다. 로컬 예제만으로 종료하지 않는다.
4. **블로그 TLS**: 출시 범위에 해당 블로그가 포함되면 가용성·인증서 신뢰 확인 전까지 조건부 차단 후보다. 포함 여부와 담당 확인이 필요하다.

## 재점검 완료 항목과 남은 판단

이번에 완료한 것은 기존 자료 보존 확인, 선택된 증적 해시 대조, 저장 코드의 입력/메시지/인증 목적지·토큰 처리 재현, 저장 헤더/CSP 검토, 기존 로컬 32건 재검증과 새 헤더 예제 7건 검증이다. 총 **로컬 테스트 39건 통과**이며 별도 구문 재현 결과와 구분했다.

실제 서비스 소스·승인 환경·계정·배포 자료가 없어 필수 서버 및 수정 통합 검증은 완료하지 못했다. **출시 안전 판정은 계속 보류한다.** 다음 실행은 위 담당자가 자료와 온라인 조건을 제공한 뒤, 원본 소스 분석·패치와 격리 환경의 동일 조건 변경 전후 검증으로 이어가야 한다.
