# 승인 대상 웹 보안 설정 점검기

**엔진 포함판 추가:** ARTEX Global 원본 소스와 공식 이미지 실행 구성을 포함합니다. `run.bat`의 **2번**으로 ARTEX를 시작합니다. **[ARTEX 설치·실행·입력 예시 안내](ENGINE.md)**를 먼저 확인하세요. 아래 설명은 메뉴 1번의 경량 점검기에 관한 것입니다. 두 모드는 별도 UI·별도 작업으로 운영됩니다.

## 웹 화면으로 실행 (Windows)

1. ZIP을 압축 해제하고 Node.js 22 이상을 설치합니다.
2. **`run.bat`을 더블클릭 → 1번**을 선택합니다. 실행 창을 열어 두면 브라우저가 `http://127.0.0.1:8787`을 엽니다. 자동으로 열리지 않으면 주소를 직접 입력하세요.
3. 웹 화면에서 프로젝트, 승인번호, 수행자, 승인 기간, 허용 origin, URL을 입력합니다. 예시 도메인과 기간을 회사 승인 정보로 변경하세요.
4. **계획 검토**로 요청 없이 범위를 확인합니다. **설정 JSON 저장**으로 승인 요청에 첨부할 수 있습니다.
5. 회사 승인 후 승인 체크박스를 선택하고 **계획 검토 → 점검 실행**을 누릅니다. 승인 기간 밖의 실행은 거부합니다.
6. 진행 현황과 검토 항목을 확인합니다. **중단**은 현재 요청과 다음 요청 대기를 취소합니다. **결과 JSON 다운로드**로 보고서를 받습니다. 완료·중단 결과는 `reports` 폴더에도 저장됩니다.
7. 실행 창에서 Ctrl+C로 서버를 종료합니다. 브라우저를 닫아도 서버와 점검은 계속 실행될 수 있으므로, 점검 중단 또는 서버 종료를 직접 하세요.

다른 사람에게 ZIP을 전달하면 해당 PC에서 실행할 수 있습니다. 서버는 로컬 PC의 127.0.0.1에만 바인딩하며 공용 웹사이트로 배포하지 않습니다. 사내 대상에 접근 가능한 PC/VPN에서 실행하세요. 8787 포트가 사용 중이면 기존 실행 창을 확인하세요. Node.js는 자동 설치하지 않습니다.

웹 화면은 동일 출처·실행 토큰·Host 검사를 수행하며, 보고서는 HTML로 해석하지 않고 텍스트로 표시합니다. 다중 사용자 로그인·전자결재·조직 권한 통제는 제공하지 않습니다. 승인 체크는 사용자의 확인 입력입니다. 공동 서버나 외부 공개 서비스로 사용하려면 별도의 인증·관리자 대상 범위 정책이 필요합니다.

구성 파일 불러오기 시 승인 체크는 해제됩니다. 입력을 변경하면 계획을 다시 검토해야 합니다. 현재 작업 한 개만 실행하며 서버 재시작 후 진행 상태는 복원하지 않습니다. 기존 보고서는 `reports` 폴더에서 확인하세요.

Node.js 22 이상에서 추가 패키지 없이 실행하는 검토용 프로그램입니다. 한국어 안내를 제공합니다. ARTEX의 자율 점검이라는 아이디어를 참고하되, ARTEX 코드나 LLM·명령 실행 엔진을 포함하지 않는 독립 구현입니다. ARTEX 호환 플러그인이나 ARTEX 전체 기능의 배포판은 아닙니다.

참고 저장소: https://github.com/jiwoochris/artex-global 및 https://github.com/Jyuung/artex (Global에서 파생된 포크). 이 프로그램은 두 저장소를 설치하거나 실행하지 않습니다.

## 실행

PowerShell에서 이 폴더로 이동합니다. 먼저 `node --version`으로 Node.js 22 이상인지 확인하세요.

```powershell
Copy-Item example.json company.json
# 편집기로 company.json의 대상·기간·담당자·승인번호를 수정
notepad company.json
# 승인 전 제출용 계획 확인: 네트워크 요청 없음
node scan.mjs --config company.json
# 로컬 검증: 외부 서비스 접속 없음
node --test
# 회사 승인 후 approved를 true로 바꾸고 승인 시간 내 실행
node scan.mjs --config company.json --execute
```

예시 도메인은 실제 대상이 아닙니다. 승인 전에 예시 설정으로 실행 모드를 사용하지 마세요. 프로그램의 `approved` 필드는 사용자 입력이며 승인 사실을 인증하거나 전자결재와 연동하지 않습니다.

## 입력값

|항목|설명|예시|
|---|---|---|
|project|제출할 점검 이름|사내 포털 사전 점검|
|approval.id|회사 승인·변경관리 번호|SEC-2026-0123|
|approval.operator|수행자와 부서|홍길동 / 정보보안팀|
|approval.approved|실제 회사 승인 후 true 지정|false|
|approval.validFrom / validUntil|시간대 포함 승인 기간, 시작 이상·종료 미만|2026-11-10T09:00:00+09:00|
|allowedOrigins|허용한 프로토콜·호스트·포트 목록. 경로·와일드카드 불가|["https://portal.example.com:8443"]|
|targets|실제로 조회할 URL 1~20개. 각각 허용 origin과 일치해야 함|["https://portal.example.com:8443/login"]|
|intervalMs|응답 후 다음 요청까지 대기, 1000~60000ms|1500|
|timeoutMs|요청별 전체 제한시간, 1000~30000ms|10000|

쿼리·fragment·URL 내 ID/비밀번호는 거부합니다. 승인 origin이 같아도 해당 호스트가 연결하는 실제 IP, DNS 변경, 공유 호스팅은 프로그램이 소유권을 확인하지 않습니다. 네트워크 담당자가 대상 DNS·포트·프록시·송신 정책을 함께 검토해야 합니다. 리다이렉트 뒤의 대상은 자동 점검하지 않으므로 별도 승인 URL로 입력해야 합니다.

## 점검과 결과

각 대상에 비인증 GET 1회, 동시에 1개 요청만 보냅니다. 경로 탐색·크롤링·로그인·취약점 페이로드·명령 실행은 포함하지 않습니다. GET 요청도 서버 로그를 남기며 잘못 설계된 애플리케이션에서는 상태를 변경할 수 있으므로 대상 경로를 사전에 검토하세요.

- HTTP 사용, HTTPS의 HSTS 헤더
- HTML의 CSP 및 프레임 제한 헤더 존재 여부
- X-Content-Type-Options의 nosniff
- 응답 쿠키의 Secure, HttpOnly, SameSite 속성 존재 여부
- 현재 TLS 연결의 인증서 검증과 협상 프로토콜·암호군 관찰

인증서 검증을 끄는 옵션은 없습니다. TLS 연결 실패는 네트워크 오류와 구분하여 확정 취약점으로 판정하지 않습니다. 사내 CA 환경은 Node.js의 신뢰 CA 설정을 관리자가 구성해야 합니다. 레거시 TLS 프로토콜·모든 암호군을 탐색하는 도구는 아닙니다.

429·5xx·네트워크/TLS 오류 시 중단합니다. 승인 종료 시각을 다음 요청 전에 검사하고 남은 시간으로 요청 제한시간을 줄입니다. 재시도하지 않습니다. Ctrl+C로 즉시 중지할 수 있으나 강제 중지 시 진행 중 보고서는 저장되지 않을 수 있습니다.

결과는 실행한 작업 디렉터리의 `reports/review-시각.json`에 저장됩니다. URL, 승인 메타데이터, 상태코드, TLS 관찰, 검토 항목, 중단 사유를 포함합니다. 본문·쿠키 값·전체 헤더는 저장하지 않습니다. URL 경로 자체는 기록되므로 경로에 개인정보·토큰을 넣지 마세요. 보고서 파일도 사내 정책에 따라 보관하세요.

종료 코드: 0=계획 출력 또는 수집 완료, 1=입력/파일 오류, 2=일부 수집 후 중단. 0은 보안 안전 판정을 뜻하지 않습니다. 보고서의 `review`는 담당자 검토 항목입니다. CSP 정책 품질, 쿠키의 실제 용도, 인증·권한 통제, XSS·SQL injection·SSRF·업무 로직 등은 검증하지 않습니다.

## 회사 제출 문안

> 목적: 승인된 웹서비스의 공개 응답 보안 설정을 확인하고 개선 후보를 식별한다.
>
> 범위: company.json에 명시한 origin과 URL만 수행한다. 점검 기간, 담당자 및 승인번호는 동일 파일로 제출한다.
>
> 방법: URL당 비인증 GET 1회, 최대 20개 URL, 동시 요청 1개, 최소 1초 간격. 리다이렉트 추적 및 자동 재시도 없음. 429/5xx/통신 오류 시 중단한다.
>
> 수집: 응답 상태, 일부 보안 설정 관찰, TLS 연결 정보. 응답 본문 및 쿠키 값 저장 없음.
>
> 운영 영향: 요청 로그와 소량의 연결 부하가 발생한다. 상태 변경이 없는 경로를 서비스 담당자가 확인한다. 중단 연락 담당자 및 연락 수단: [작성].
>
> 산출물: JSON 관찰 보고서 및 담당자의 오탐·적용 가능성 검토. 보관 위치·접근 권한·삭제일: [작성].
>
> 승인 요청: 시스템 소유자·운영 담당자·정보보안 담당자가 대상, 수행 시간, 송신 IP 및 중단 연락 체계를 확인한 후 승인한다.

이 패키지 작성 과정에서는 회사 또는 외부 실서비스에 점검 요청을 보내지 않습니다. 로컬 테스트와 계획 출력만으로 검증할 수 있습니다.
