# 라이나생명 검색 노출 종료 후보 페이지 보안 점검 보고서

작성일: 2026-10-30 KST  
점검 성격: 공개 검색 기반 자산 후보 조사 및 비파괴 구성 점검  
판정: **종료된 채용·이벤트의 검색 노출을 확인했으나, 관리가 중단된 서버 또는 악용 가능한 취약점은 확정하지 않음.**

## 1. 주요 결과

- 검색 질의 24개로 종료·과거 채용·이벤트·서비스 종료 단서를 조사했다. 공개 URL 5개를 고정하여 일반 GET을 각 1회 시도했고 4개는 HTTP 200, 1개는 이 실행 환경에서 DNS 해석 실패(ENOTFOUND)였다.
- 2025년 채용 홍보 페이지는 모집 종료일이 지났는데도 검색 및 공개 접속이 가능했다. 정적 보관 목적일 수 있으므로 미관리 자산으로 단정하지 않는다.
- 2024년 7월 이벤트 상세 페이지는 검색 결과에 종료 안내가 존재한다. 종료 이벤트를 공개 이력으로 보관하는 것은 그 자체로 취약점이 아니다.
- 오래된 모바일 퀴즈 이벤트가 검색된다. 검색 수집본에는 개인정보 입력 안내가 있지만 이번 원본 HTML에서는 숨김 입력이 있는 폼 틀만 확인했다. 실제 개인정보 입력 화면과 서버 접수 가능 여부는 검증하지 않았다.
- 200 응답 4개 모두 CSP 응답 헤더와 HTML meta 정책, X-Frame-Options를 관측하지 못했다. 프레임 정책·스크립트 실행 정책 검토가 필요하나 공격 성공을 뜻하지 않는다.
- 일부 페이지는 오래된 jQuery 이름의 파일을 참조한다. 이번에는 파일 본문·실행 버전·보안 패치·취약 함수 사용 여부를 확인하지 않아 CVE를 확정 적용하지 않는다.
- **검색 포털 전체 결과 또는 라이나 관련 모든 미운영 사이트의 전수 목록이 아니다.** 자산대장·도메인 목록·위탁사 계약·소유자 확인이 있어야 전수 점검과 미운영 확정이 가능하다.

## 2. 조사 범위와 분류 기준

공개 웹 검색 도구를 사용했다. 네이버·구글·다음 포털 UI 각각의 전수 검색은 수행하지 않았다. 네이버 블로그 제한 결과는 우회하지 않았다. 검색 수집 시각·본문과 실제 GET 결과가 다를 수 있어 구분했다.

| 분류 | 판단 기준 |
|---|---|
| 기간 종료 확인 | 공고/페이지에 종료일 또는 종료 문구가 있고 기준일보다 과거 |
| 종료 후보 | 과거 연도·광고 확인 기간 등 단서만 존재. 실제 캠페인 종료는 미확인 |
| 접속 확인 | 일반 GET에 HTTP 200. 사업 운영/유지보수 여부와는 별개 |
| 접속 미확인 | DNS/네트워크 오류. 폐쇄·등록 만료·탈취 가능성을 뜻하지 않음 |
| 보존/운영 목적 미확인 | 사이트 소유자의 폐쇄·보관·운영 결정 증빙이 없음 |
| 제외/참고 | 제3자 채용 공고·대학 게시물·기사·앱 소개. 라이나가 관리하는 공격 표면이라고 간주하지 않음 |

이번 회차에는 공격 구문, 로그인, 폼 제출, 개인정보 입력, API 호출, 경로 추측, 디렉터리/포트 스캔, 대량 호출, DNS 변경·등록 시도, AI 입력 시험을 수행하지 않았다. 이전 회차의 요청은 이번 회차 요청 수에 포함하지 않았다.

## 3. 자산 후보 및 개별 결과

### C01 — 2025년 채용 홍보 페이지

URL: https://nhrsite.com/lina25/

- 검색 직접 노출 및 일반 GET 200. 제목은 2025년 채용 홍보이며 본문에 9월 1~19일 모집 기간과 외부 채용 사이트 지원 링크가 있다. 별도 대학 공고도 2025-09-19 마감을 명시한다. [검색 대상](https://nhrsite.com/lina25/), [대학 공고 근거](https://biz.korea.ac.kr/cdc/recruitment/recruitment_view?cate=&key=&keyfield=&no=13705&page=)
- 분류: **모집 기간 종료 / 페이지 공개 / 유지보수 및 보존 목적 미확인**.
- 관측: CSP·프레임 제한·HSTS·nosniff 응답 헤더 미관측. CSP meta·일반 robots meta 미검출. 외부 CDN 스크립트 참조 있음. 폼/입력 태그 미검출은 JS 동작 후의 부재를 보장하지 않는다.
- 조치: 인사/위탁사에 보존 목적 확인. 종료 안내를 명시하고 과거 지원 동선의 유효성을 검토한다. 정적 보관이면 불필요한 스크립트·분석 태그를 제거하고 보안 헤더를 적용한다. HTTP 200 유지 자체를 결함으로 판단하지 않는다.

### C02 — 공고에 남아 있는 2025년 채용 도메인

URL: https://linakorea-career2025.com/

- 대학·채용 공고에서 해당 도메인을 홍보 주소로 확인했다. [SUNY Korea 공고](https://www.sunykorea.ac.kr/en/html/sub04/040404.html?GotoPage=5&mode=V&no=bfae7bc89acf961be8dccabc153bbe3a), [삼육대 공고](https://www.syu.ac.kr/blog/%EB%9D%BC%EC%9D%B4%EB%82%98%EC%83%9D%EB%AA%85-2025%EB%85%84-%EC%8B%A0%EC%9E%85-%EA%B3%B5%EA%B0%9C-%EC%B1%84%EC%9A%A9-9-19/)
- 일반 GET 시도는 ENOTFOUND로 끝나 HTTP 응답을 얻지 못했다. 웹 열기 도구의 502 오류도 있었으나 원 서버의 502 응답으로 확정하지 않는다.
- 분류: **종료 공고에 연결된 과거 도메인 / 현재 접속 미확인**.
- 조치: 소유자가 등록·갱신 상태, DNS, 기존 리다이렉트 의도, 외부 공고의 링크 교체 필요성을 확인한다. 향후 유사 브랜드 사칭에 악용되지 않도록 도메인 수명주기를 관리한다. **도메인 만료나 탈취 취약점을 확인한 것은 아니다.**

### C03 — 채용 접수 홈페이지

URL: https://linakorea.careerlink.kr/

- 2025년 공고에 접수 경로로 등장하고 현재 일반 GET 200. 제목은 라이나생명 채용 홈페이지다. [채용 공고](https://www.invione.com/jobs/recruitment/open/detail/134147)
- 분류: **운영 상태 미확인 / 종료 자산 판정 제외**. 특정 공고 종료를 채용 플랫폼 전체 종료로 확대하지 않는다.
- 관측: HSTS max-age=63072000 있음. CSP·프레임 제한·nosniff 미관측. 최초 HTML은 클라이언트 렌더링에 필요한 코드가 많아 공고 접수 상태·개인정보 처리 상태는 미확인이다.
- 조치: 운영자가 현재 공고와 2025년 공고의 종료 상태를 확인하고 위탁 채용 플랫폼에 보안 헤더·관리자 접근·개인정보 보존/삭제 증빙을 요청한다. 공개 응답의 Cache-Control: public만으로 개인정보 캐시 노출이라고 판단하지 않는다.

### C04 — 종료된 2024년 7월 가입감사 이벤트

URL: https://direct.lina.co.kr/event/detail?evtSeq=1266

- 검색 수집본은 이벤트 기간 2024-07-01~2024-07-31과 종료 안내를 표시한다. 이번 GET은 200이지만 최초 HTML에서 날짜·종료 문구가 확인되지 않아 검색 수집본의 내용과 분리했다. [이벤트 검색 근거](https://direct.lina.co.kr/event/detail?evtSeq=1266)
- 분류: **이벤트 종료 확인 / 상세 페이지 공개 / 서버 미운영 아님**.
- 관측: HSTS·nosniff·no-store 있음. CSP·프레임 제한 미관측. jQuery 3.7.1 경로 다음 1.12.4 경로 참조.
- 조치: 이력 보존 정책 확인, 실제 접수 API의 기간 만료 검사 여부를 소스/격리 환경에서 검증. 중복·구버전 참조 정리와 프레임 정책 설정. 실제 API에는 접근하지 않았다.

### C05 — 오래된 모바일 퀴즈/상담 이벤트

URL: https://m.lina.co.kr/telanding/ob/Quiz_DT_reward.htm?adtype=LMS_C3&event=C3_T23_SSGPAY&media=20240807_30_BASKIN&source=DENTAL

- 검색 수집본은 개인정보 입력 안내와 2024-07-08~2025-07-07 광고 확인 기간을 포함한다. 이벤트 종료일은 별도 문자 안내에 따른다고 되어 있어 **광고 확인 기간 경과를 이벤트 종료 확정으로 해석하지 않는다**. [검색 근거](https://m.lina.co.kr/telanding/ob/Quiz_DT_reward.htm?adtype=LMS_C3&event=C3_T23_SSGPAY&media=20240807_30_BASKIN&source=DENTAL)
- 이번 GET은 200. 초기 HTML에는 폼 1개와 숨김 입력 5개가 존재한다. 검색본의 개인정보 입력 화면이 현재 브라우저에서도 동작하는지, 서버가 접수를 받는지는 미검증이다.
- 분류: **종료 후보 / 재검토 우선순위 높음 / 미운영 미확정**.
- 관측: HSTS·nosniff·no-store 있음. CSP·프레임 제한 미관측. jQuery 3.7.1·1.12.4·1.11.2로 보이는 경로들이 함께 참조됨. 실제 라이브러리 취약성은 미확인이다.
- 조치: 마케팅/준법/개인정보 담당자가 현행 캠페인 여부를 먼저 확인한다. 종료됐다면 화면뿐 아니라 접수·문자·경품 등 연결 처리를 서버에서 종료하고 개인정보 보존 정책을 확인한다. 현재 캠페인이면 안내 문구·동의 내용과 코드 의존성을 검토한다.

| R-05 중간 | C01 | 여러 보안 헤더 미관측, 외부 CDN 사용 | HTTPS 운영 확인 후 HSTS, MIME 유형 확인 후 nosniff, CDN 버전 고정·무결성 정책 검토 |
| R-06 관리 | 전체 | 운영/폐쇄 소유자 증빙 없음 | 도메인·위탁사·접수 API·DB·배포 책임자와 종료일을 자산대장에 기록 |

보안 헤더 부재는 보완 항목이다. XSS·클릭재킹·개인정보 유출이 성공했다는 뜻은 아니다. 미관리 여부, 보유 개인정보, 서버 인가·패치·로그는 이번 공개 점검으로 확인하지 못했다.

## 6. 점검 방법과 재현

### 6.1 검색 및 중복 제거

검색어 24개는 [검색 기록](../audit/retired-site-search-log.md)에 남겼다. 브랜드명과 종료·연도·채용·이벤트 표현, 공식 도메인 제한을 조합했다. 검색 결과에서 직접 URL과 공고에 실린 링크를 추출했다. 이벤트 번호·경로·서브도메인을 추측하거나 확장하지 않았다. 대학 미러·URL의 페이지 이동 파라미터는 별도 독립 시스템으로 세지 않는다. 검색엔진에서 결과가 안 나온 사실을 사이트 부재로 판정하지 않는다.

### 6.2 공개 응답 수집

고정 목록 C01~C05만 대상으로 각 일반 GET 1회, 요청 사이 최소 1.5초, 요청당 10초, 본문당 1 MiB 제한을 사용했다. 인증정보를 보내지 않고 리다이렉트·참조 JS/CSS·폼을 따라가지 않았다. DNS 실패는 응답 실패로 기록했다. HTTP 비200에서는 본문 수집/재시도를 하지 않았다. TLS 검증을 비활성화하지 않았다.

```powershell
# 실제 외부 요청을 최대 5회 다시 발생시킴. 오프라인 명령이 아님.
node audit/collect-retired-candidates.mjs
```

요청 시각·URL·상태·선별 헤더·본문 SHA-256을 JSON으로, 성공한 본문을 HTML로 보관했다. 쿠키 원문은 결과 JSON에 저장하지 않았다. 외부 서버 로그는 접근하지 못했으며 요청 흔적을 삭제/은폐하지 않았다. 웹 검색/열기 도구의 요청은 위 수집 스크립트 5회와 별개이고 그 도구의 총 네트워크 요청 수는 확인할 수 없다.

### 6.3 정적 검사

CSP·Report-Only·X-Frame-Options·HSTS·nosniff·캐시·검색 로봇 헤더를 확인했다. HTML에서 CSP/robots meta, script src, 폼/입력 태그를 추출했다. 이는 정규식 기반 UTF-8 텍스트 검사이며 브라우저 DOM 파서·렌더링·JS 실행을 대체하지 않는다. robots meta 미검출은 robots.txt가 없다는 뜻이 아니다. robots.txt는 요청하지 않았다.

### 6.4 운영 종료 확인 방법 — 담당자 후속 절차

마케팅/인사 소유자 확인 → 공고/캠페인 종료일 확정 → 웹·API·DB·SMS/경품·분석 연동 목록 대조 → 보존/폐쇄 결정 → 변경 승인 → 테스트 환경 검증 → 운영 반영 후 재점검 순서로 진행한다. 화면에서 신청 버튼을 숨기는 것만으로 접수 종료를 완료 처리하지 않는다.

### 6.5 추가 취약점 검증 방법 — 이번 미수행

| 검사 | 필요한 자료 | 테스트 환경 합격 기준 |
|---|---|---|
| 종료 후 접수 방지 | 접수 API 소스, 테스트 캠페인 | 종료 캠페인의 합성 신청 거부; DB 저장·문자·경품 발송 없음 |
| XSS | 실제 템플릿·렌더러 | 입력/외부 응답을 텍스트로 출력 또는 적절히 정화; 브라우저 실행 구문 미실행 |
| 개인정보 접근 권한 | 합성 A/B 계정·자료 | A가 B의 데이터·첨부·내보내기에 접근 불가. 정상 A 동작은 성공 |
| 호출·비용 제한 | 낮춘 테스트 한도 | 초과 전에 비싼 작업 거부; 다른 정상 사용자 유지 |
| 도메인·위탁사 수명주기 | 등록/DNS/계약/소유자 증빙 | 미사용 연결 제거, 도메인 회수·유지 책임 확정. 제3자 자원 인수 시도 없음 |
| 로그·대응 | 테스트 관제 환경 | 합성 이벤트의 탐지·담당자 확인·필요 세션 회수 기록 확보 |

## 7. 폐쇄와 검색 제외 방법

완전 폐쇄라면 필요한 자료 보존 후 기능·연동·계정/키를 정리하고 해당 자원에 404/410을 반환한다. 동등한 후속 페이지가 있으면 적절한 리다이렉트를 검토한다. 공개 아카이브를 유지하면서 검색에서만 제외하려면 noindex를 사용하되 검색로봇이 해당 지시를 읽을 수 있어야 한다. 민감 자료는 접근통제로 보호한다. **noindex와 robots.txt는 보안 접근통제가 아니다.** [Google 삭제 지침](https://developers.google.com/search/docs/crawling-indexing/remove-information), [Google 404/410 안내](https://support.google.com/webmasters/answer/2445990?hl=en)

네이버 서치어드바이저와 Google Search Console에서 소유자 권한으로 검색 제외·갱신을 요청한다. 외부 대학/채용 사이트의 본문 링크도 정정한다. 검색 제외는 서버 폐쇄나 취약점 수정을 대신하지 않으며 즉각 반영을 보장하지 않는다. [네이버 검색 제외](https://searchadvisor.naver.com/guide/faq-serpremove), [네이버 수집·검색 제외 절차](https://searchadvisor.naver.com/guide/request-crawl)
