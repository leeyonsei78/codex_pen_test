# v7: LLM 간편 설정

이번 변경은 **LLM 연결 화면 개선**입니다. 공급자·API 키·모델을 입력하고, API 형식과 Base URL은 자동 설정합니다. 사내 API·호환 서버에서만 고급 설정을 사용합니다. 자동 탐지 → 사람 승인 → 수정 적용 → 재점검 통합 기능을 완성한 버전은 아닙니다.

## 기존 사용자는 데이터 보존 후 업데이트

1. 기존 경량 서버(8787)가 켜져 있다면 해당 창에서 Ctrl+C로 종료합니다. ARTEX(8790)는 유지할 수 있습니다.
2. 현재 실행 폴더를 백업합니다. 특히 **engine-runtime/.env 및 data를 보존**합니다. Docker DB 볼륨도 유지합니다.
3. 새 ZIP의 artex-review 안 파일들을 **기존 artex-review 폴더에 덮어씁니다**. 새 ZIP에는 engine-runtime이 없으므로 기존 폴더를 삭제하거나 새 폴더로 교체하지 마세요. 새 폴더에서 엔진을 초기화하면 기존 DB 비밀번호와 달라져 연결이 실패할 수 있습니다.
4. 기존 실행 폴더의 run.bat → **9번**을 선택합니다. http://127.0.0.1:8787/llm-settings.html 이 열립니다. 서버 창은 열어 둡니다.

## 사용 순서

1. ARTEX가 8790 포트에서 실행 중인지 확인합니다.
2. 간편 설정 화면에서 ARTEX 관리자 비밀번호로 연결합니다. 초기 비밀번호 생성은 ARTEX /setup에서 먼저 완료해야 합니다.
3. 공급자를 선택합니다. OpenAI는 기본 Responses API, Anthropic은 Messages API가 자동 설정됩니다. 키를 모델에 맞춰 발급하는 것이 아니라 공급자·계정의 키를 사용합니다.
4. 실제 API 키 입력 → 모델 조회 → 모델 선택 또는 직접 입력 → 프로필 이름 지정 → 연결 테스트.
5. 저장 시 기본 프로필로 활성화할지 확인하고 **ARTEX에 프로필 저장**을 누릅니다. 테스트 후 설정이 바뀌면 재테스트해야 합니다. 테스트는 비용이 발생할 수 있습니다.
6. 새 프로필은 ARTEX 시스템 → LLM에서 확인합니다. 활성화를 선택하지 않으면 자동 대체 풀에서 제외해 저장합니다. 첫 프로필의 기본 지정 등 ARTEX 자체 동작은 ARTEX 화면에서 확인하세요. 활성화는 실행 중 작업에 영향을 줄 수 있습니다.
7. 사용 후 **연결 해제**합니다. 브라우저를 닫는 것만으로 인증이 해제되지는 않습니다. 서버 인증은 최대 15분 후 만료됩니다.

키는 브라우저 저장소·경량 보고서·로컬 파일에 기록하지 않습니다. 프로필 저장을 누르면 ARTEX의 DB에 저장됩니다. 관리자 JWT는 로컬 서버 메모리에만 유지합니다. 모든 연결 작업은 기존 로컬 토큰과 동일 출처 검사를 거칩니다.

이 화면은 원본 컨테이너 UI를 교체하지 않습니다. 별도 간편 화면에서 ARTEX의 기존 API를 통해 실제 저장하는 방식입니다. 단일 운영자 로컬 사용을 전제로 하며 여러 사용자에게 공유하는 서버로 공개하지 마세요.

실제 API 키는 제공되지 않아 공급자와의 실연결은 테스트하지 않았습니다. 모의 ARTEX 서버에서 API 계약·저장·인증·변경 후 재테스트·민감정보 미반환을 검증합니다.
