# ARTEX 엔진 포함판

ARTEX Global **v0.3.15-global.1** 원본 소스 전체를 `engine/`에 포함합니다. 고정 소스 커밋: `d6964594a0221cd921b85056d604bce9d8ce54df`.
원본: https://github.com/jiwoochris/artex-global/releases/tag/v0.3.15-global.1
라이선스·저작권 고지: `engine/LICENSE`, `engine/README.ko.md`. 엔진 소스를 수정하지 않았습니다. 실행에는 동일 릴리스의 공식 컨테이너 이미지를 사용합니다. ZIP은 소스 포함판이며 이미지·바이너리·모델을 미리 탑재한 오프라인 실행판은 아닙니다.

## 준비와 실행

1. Node.js 22 이상과 Docker Desktop을 설치합니다. Docker Desktop에서 Linux 컨테이너 엔진이 실행 완료되어야 합니다.
2. `run.bat` 더블클릭 → **2** 선택. 최초 실행 시 공식 ARTEX 이미지와 PostgreSQL 이미지를 내려받습니다. 인터넷, 디스크 여유 공간 및 이미지 다운로드 시간이 필요합니다. 이미지 수신이 차단된 회사 환경에서는 사내 담당자의 레지스트리 허용 설정이 필요합니다.
3. 시작 성공 후 `http://127.0.0.1:8790`이 열립니다. 처음이면 `run.bat`을 다시 열어 **5**를 선택하고 표시되는 setup token을 `/setup` 화면에 입력해 관리자 비밀번호를 만듭니다. 토큰은 외부에 공유하지 마세요.
4. ARTEX에 로그인해 시스템 설정에서 LLM 공급자·모델·API 키를 입력합니다. API 키는 이 패키지에 포함되어 있지 않습니다. 조직에서 승인한 모델과 엔드포인트를 사용하세요. LLM 호출 비용이 발생할 수 있으며 점검 정보가 해당 공급자로 전송될 수 있습니다.
5. 표시 언어를 한국어로 선택합니다. 새 점검 작업의 범위와 목표는 승인된 격리 테스트 환경으로 지정하고, ARTEX의 계획과 도구 승인 설정을 검토한 뒤 작업을 시작합니다. 본 패키지는 작업을 자동 생성하거나 점검을 자동 시작하지 않습니다.

## 메뉴

|번호|기능|
|---|---|
|1|기존 단일 GET 기반 보안 설정 점검기 (8787)|
|2|ARTEX와 PostgreSQL 시작 + ARTEX 웹 UI 열기 (8790)|
|3|ARTEX와 PostgreSQL 중지, 데이터 보존|
|4|컨테이너 상태 확인|
|5|최초 설정 토큰 표시 (민감정보)|
|6|엔진 로그 확인 (민감정보 포함 가능)|
|7|API 형식·모델 ID 입력 예시와 확인 링크를 안내 화면으로 열기|
|8|完整한 사용 설명서 화면 열기|

**설정이 낯설다면 메뉴 7을 먼저 사용하세요.** Docker 없이도 안내 화면을 열 수 있습니다. OpenAI Responses, OpenAI Chat Completions, Anthropic, 사내 호환 API별 예시를 선택할 수 있습니다. 원본 ARTEX 컨테이너의 화면을 변경한 것은 아니며, 안내 페이지를 옆에 두고 ARTEX 시스템 → LLM에 입력하는 방식입니다. 공식 모델 목록에서 반환된 `id`를 사용하고 문서상의 예시 모델 사용 가능성은 연결 테스트로 확인하세요.

ARTEX 컨테이너는 실행 창을 닫아도 계속 동작합니다. 종료할 때 **3**을 사용하세요. 재부팅 후 자동 기동은 꺼 두었습니다. PostgreSQL은 호스트 포트를 공개하지 않으며, 웹 UI와 트래픽 프록시 포트는 로컬에만 바인딩합니다.

## 입력 예시와 범위

|위치|입력|예시|
|---|---|---|
|ARTEX 초기 설정|설정 토큰|메뉴 5에서 확인한 무작위 값|
|ARTEX 초기 설정|관리자 비밀번호|담당자가 생성한 고유 비밀번호|
|시스템 설정|LLM 공급자·모델|회사 승인 공급자 및 사용 가능한 정확한 모델 ID|
|시스템 설정|API 키|회사 발급 키. 문서·보고서에 기재 금지|
|작업 생성|대상 범위|소유한 격리 테스트 앱의 URL/IP|
|작업 생성|목표|승인번호 SEC-2026-0123. 격리 테스트 앱의 웹 취약점 검증. 범위·시간·허용 기법·제외 항목을 승인서에 따라 명시|

컨테이너에서 `127.0.0.1`은 Windows PC가 아닌 컨테이너 자체입니다. PC에서 별도로 실행 중인 테스트 앱은 Docker Desktop의 `host.docker.internal`과 실제 테스트 앱 포트를 사용할 수 있습니다. 예: `http://host.docker.internal:3000` (해당 앱을 실제 실행하고 승인한 경우에만). 다른 컨테이너의 앱은 연결한 Docker 네트워크와 서비스명에 따라 주소가 달라집니다.

기존 경량 점검기의 승인 체크·시간 제한·origin 허용 목록·중단 버튼은 **ARTEX 작업을 제어하지 않습니다**. ARTEX는 자체 로그인·작업·데이터·승인 체계를 사용합니다. 경량 점검기의 JSON을 ARTEX에 자동 전달하지 않습니다. 회사 제출 시 두 모드의 기능·영향·전송 데이터 차이를 반영하세요.

## 데이터·오류 대응

- `engine-runtime/.env`: 최초 시작 시 DB 비밀번호·setup token 자동 생성. Windows 사용자 계정과 파일 접근 권한으로 보호하세요.
- `engine-runtime/data/`: ARTEX 파일·설정. PostgreSQL 데이터는 Docker의 `artex-review-engine_engine_pgdata` 볼륨에 보존됩니다.
- LLM 키·보고서·트래픽·데이터가 들어간 런타임 폴더는 배포 ZIP에 넣지 마세요. DB 비밀번호를 바꿀 때는 PostgreSQL 계정 변경도 함께 해야 합니다. `.env`만 삭제·재생성하면 기존 DB에 로그인하지 못할 수 있습니다.
- Docker 오류: Docker Desktop을 먼저 실행하고 Linux containers 모드인지 확인하세요. `node engine-control.mjs check`로 사전 확인할 수 있습니다.
- 포트 오류: 기존 8790/8791 서비스와 충돌하는지 확인하세요. 8787 경량 점검기와는 동시 실행 가능합니다.
- 시작 실패: 메뉴 4와 6에서 확인하고 필요 시 메뉴 3으로 컨테이너를 중지하세요. 실패 뒤 이미 시작된 PostgreSQL이 남을 수 있습니다.

현재 작성 환경에서는 Docker 엔진에 연결되지 않아 실제 ARTEX 컨테이너 기동·LLM 작업 실행은 검증하지 못했습니다. 소스 릴리스 고정, Compose 구성 구문, 런처 검사 및 기존 로컬 테스트 결과를 별도 확인합니다.
