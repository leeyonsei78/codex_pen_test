LLM 설정, 무엇을 넣나요?

사용하는 서비스 형식을 고르면 ARTEX 입력 예시와 모델 ID 확인 방법을 볼 수 있습니다.

01 사용하는 API 형식 선택

일반 연결은 run.bat → 9번 간편 설정을 사용하세요. 공급자 선택 시 형식과 주소가 자동 설정됩니다. 아래 표는 고급 설정을 이해하기 위한 참고입니다.

ARTEX 입력 항목예시 값확인할 내용

이 페이지는 안내용입니다. 실제 설정은 간편 설정 화면 또는 ARTEX → 시스템 → LLM에서 입력합니다. 이 안내 페이지 자체에는 API 키를 입력·저장·전송하는 기능이 없습니다. 예시 모델은 최신 추천이나 계정별 사용 가능성을 보장하지 않습니다. 고정된 구버전 ARTEX와 선택 모델의 호환성은 연결 테스트로 확인하세요.

02 모델 ID는 어디에서 확인하나요?

    모델 목록 응답을 받았다면

    표시 이름(display_name) 대신 data 배열의 id 값을 그대로 복사합니다. 다음은 구조를 보여주는 가상 예시입니다.

    {
  "data": [
    { "id": "company-approved-model", "display_name": "회사 AI 모델" }
  ]
}

    ARTEX의 모델 칸에는 company-approved-model을 입력합니다. 이 이름은 가상 값이므로 실제 응답의 ID로 바꿔야 합니다.

    공식 문서에 있는 모델도 회사 계정·프로젝트 권한에 따라 사용할 수 없을 수 있습니다. 해당 키의 모델 목록과 회사 허용 목록을 함께 확인하세요.

    03 초기 관리자 설정과 연결 확인

    1. run.bat → 2번으로 ARTEX를 시작합니다.
    2. run.bat → 5번에서 setup token을 확인합니다.
    3. 초기 설정 화면에 토큰과 본인이 정한 관리자 비밀번호(최소 8자)를 입력합니다.
    4. 사용자명 ARTEX와 만든 비밀번호로 로그인합니다.
    5. 시스템 → LLM에서 프로필 이름, API 형식, 모델 ID, Base URL, API 키를 입력합니다.
    6. 연결 테스트 성공 여부를 확인하고 저장합니다. 테스트가 실패하면 오류를 확인해 형식·주소·권한을 다시 확인합니다.
    오류가 나면 확인할 항목
    • 401/403: 키, 프로젝트 권한, 사내 접근 정책 확인
    • 404: 모델 ID와 API 주소·형식 확인
    • 429: 사용량·호출 한도 확인
    • 연결 시간 초과: VPN·프록시·방화벽 확인

    오류코드만으로 원인을 확정할 수 없습니다. 공급자의 상세 오류 메시지를 함께 확인하세요.

    확인한 공식 문서: 2026-11-09. 사내 API 주소와 키는 담당자에게 받으세요. 안내 페이지의 예시를 그대로 사용하면 사내 서비스에 연결되지 않습니다.

    안내 페이지는 서버 없이 파일로도 열 수 있습니다. 실제 API 호출과 설정 저장은 ARTEX에서 수행합니다.
    현재 작성 환경에서는 Docker 연결 문제로 ARTEX 기동·자동 점검을 검증하지 못했습니다. 점검 결과는 담당자가 재현·확인하고 개선 후 재점검해야 합니다. 자동 수정 기능은 포함하지 않습니다.
