ARTEX 엔진 포함판 사용 설명서

회사 승인 범위에서 취약점 후보를 찾고, 담당자가 검증·개선하는 데 사용합니다.

01 프로그램 이해하기

모드역할 / 주소사용 범위
경량 점검127.0.0.1:8787단일 GET으로 헤더·쿠키 속성·TLS 연결 설정 관찰
ARTEX 엔진127.0.0.1:8790LLM이 자체 도구를 실행하며 작업 목표에 따라 점검

두 모드는 실행 메뉴와 안내로 연결됩니다. 작업·보고서가 통합되어 있지 않으며, 경량 점검기의 승인·시간·중단 버튼은 ARTEX를 제어하지 않습니다. 자동 수정 기능은 추가하지 않았습니다.

현재 작성 환경에서는 Docker 제어 소켓 접근 권한 오류로 ARTEX 기동·LLM 점검을 검증하지 못했습니다. 설정·런처 검사와 로컬 점검 테스트 4개를 확인했습니다.

02 준비와 회사 승인

  1. ZIP을 완전히 압축 해제하고 Node.js 22 이상을 설치합니다.
  2. Docker Desktop을 켜고 Linux 컨테이너 엔진이 준비될 때까지 기다립니다.
  3. 회사 승인 LLM의 API 형식·주소·모델 ID·키·비용 한도·데이터 전송 정책을 확인합니다.
  4. 승인서에 대상 URL/IP/포트, 제외 대상, 시간대, 허용·금지 기법, 부하 한도, 데이터 처리 기준과 중단 연락처를 적습니다.
  5. 소유한 격리 테스트 환경에서 먼저 확인합니다. ARTEX는 실제 도구 실행을 포함하므로 경량 조회와 구분해 승인받습니다.

03 처음 실행하기

  1. run.bat → 2번. 최초에는 공식 이미지 다운로드가 필요합니다.
  2. http://127.0.0.1:8790/setup 에 접속합니다.
  3. 메뉴 5번의 토큰과 직접 정한 관리자 비밀번호(최소 8자)를 입력합니다.
  4. 사용자명 ARTEX와 만든 비밀번호로 로그인합니다.
  5. 시스템 → LLM에서 연결 정보를 입력하고 연결 테스트 후 저장합니다.
  6. 표시 언어를 한국어로 선택합니다.
API 형식·모델 ID 입력 예시 보기 ↗

토큰은 초기 설정용, 비밀번호는 로그인용, API 키는 AI 서비스 인증용입니다. 서로 다른 값입니다.

04 점검부터 개선·재점검까지

  1. 작업 생성: ARTEX에서 승인 대상·목표·제외 범위를 명시합니다. 입력 내용만으로 네트워크 범위가 강제된다고 가정하지 마세요.
  2. 실행 관찰: 계획과 도구 승인 설정을 검토하고 테스트 환경에서 시작합니다. 대상 서비스 상태와 활동을 관찰합니다.
  3. 중단: ARTEX 자체 작업 제어를 사용합니다. 필요하면 run.bat → 3번으로 엔진 전체를 중지합니다.
  4. 담당자 확인: 발견 항목은 취약점 후보입니다. 재현 조건·증거·영향·오탐을 확인합니다.
  5. 개선: 개발·운영팀이 코드와 설정을 수정하고 회사 변경관리 절차로 반영합니다.
  6. 재점검: 같은 재현 조건으로 확인하고 수정 전후 증거·잔여 위험을 기록합니다.

목표 예시: “승인번호 SEC-2026-0123. 소유한 격리 테스트 앱 [실제 URL]만 점검한다. 기간·허용 기법·제외 범위·부하 한도는 승인서를 따른다. 재현 조건과 개선 권고를 기록한다.”

컨테이너의 127.0.0.1은 PC가 아닙니다. PC에서 별도로 실행 중인 소유 테스트 앱은 실제 포트에 맞춰 예: http://host.docker.internal:3000 으로 접근합니다.

06 종료·보관·오류 확인

ARTEX는 창을 닫아도 동작할 수 있습니다. 메뉴 3으로 중지합니다. 경량 서버는 Ctrl+C로 종료합니다.

engine-runtime/.env와 data 폴더 및 PostgreSQL Docker 볼륨에 설정·데이터가 남습니다. 실제 키·로그·보고서를 포함해 재배포하지 마세요.

Docker를 켰는데 Access is denied?

Docker 실행 여부와 현재 실행 계정의 소켓 접근 권한은 별개입니다. 본인 계정 터미널에서 아래 명령을 실행해 보고 회사 IT에 Docker 접근 권한을 확인하세요.

docker version
docker compose version
node engine-control.mjs check

Server 항목이 표시되지 않거나 접근 거부가 있으면 기동할 수 없습니다. 소켓을 인증 없이 외부에 공개하지 마세요.

그 밖의 시작 오류는 메뉴 4·6, LLM 오류는 형식·주소·모델 ID·키 권한·사용량·VPN 정책을 확인합니다.
