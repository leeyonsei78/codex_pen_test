결론

홈페이지 화면과 프로그램 코드에서 지금 고쳐야 할 약점이 확인되었습니다. 다만 실제로 침입을 당했거나 고객정보가 새어 나간 증거는 찾지 못했습니다. 서버 안쪽은 아직 살펴보지 못했기 때문에 "안전하다"고도 말할 수 없습니다.

확인한 것

홈페이지 화면과 그 화면이 불러오는 프로그램 코드에서 개선이 필요한 점 10건(F-01~F-10)을 확인했습니다. 이 중 5건은 설정이나 코드 한 곳을 바꾸는 수준이라 먼저 고칠 것으로 분류했습니다. F-03과 F-07은 같은 경로의 문제라 함께 고칩니다.

확인하지 못한 것

실제 침입, 로그인 정보 탈취, 고객정보 유출은 확인하지 못했습니다. 이것은 "없다"는 증명이 아니라 "이번 방법으로는 확인되지 않았다"는 뜻입니다.

아직 보지 못한 것

로그인 이후의 서버 인증, 고객별 접근 권한, 청약 정보를 담은 시스템, 대량 조회 차단, 이상 징후 탐지는 점검하지 못했습니다. 안전성을 판단하려면 이 부분의 검증이 가장 중요합니다.

결정이 필요한 것

먼저 고칠 5건의 착수 승인, 서버 검증에 필요한 자료와 시험 환경 제공, 별도 목록의 8개 사이트(23개 주소) 점검 범위 승인이 필요합니다. 아래 "결정이 필요한 사항"에 정리했습니다.

읽기 전에 이 보고서만으로 "안전하다"거나 "출시해도 된다"고 승인할 수 없습니다. 반대로 "이미 침해되었다"는 뜻도 아닙니다. 2026-10-28에 수집한 응답이 기준이므로 그 이후 이미 고쳐진 항목이 있을 수 있습니다. 조치 전에 현재 상태를 먼저 확인하십시오.

아래 숫자를 누르면 해당 항목만 "항목별 결과"에 표시됩니다. 항목은 모두 13개입니다. (F-01~F-10 10건과 정상 관측 3건)

이 점검은 어떻게 했나

쉽게 비유하면 건물을 밖에서 둘러보는 외관 점검입니다. 누구나 지나가며 볼 수 있는 간판, 출입문 표지, 창문 상태를 확인하는 것이고, 문을 두드리거나 열쇠를 넣어 보거나 안으로 들어가지는 않았습니다.

  1. 공개 정보 받아오기

    브라우저로 홈페이지에 접속할 때와 같은 방식(읽기 전용)으로 화면 구성, 응답에 붙은 안내문(헤더), 화면이 불러오는 프로그램 코드를 받아 저장했습니다. 로그인, 입력, 제출은 하지 않았습니다.

  2. 읽고 비교하기

    저장한 내용을 보안 기준과 비교했습니다. 예를 들어 "이 화면을 다른 사이트에 끼워 넣지 못하게 하는 표지가 있는가", "공개된 약점이 있는 오래된 부품을 쓰는가"를 봤습니다.

  3. 의심 부분을 컴퓨터 안에서 시험하기

    의심스러운 코드는 실제 사이트에 보내지 않고, 가짜(합성) 데이터를 넣어 내 컴퓨터 안에서만 실행해 보았습니다. 이렇게 하면 실제 서비스에 영향을 주지 않고 "코드가 이렇게 동작한다"는 근거를 얻을 수 있습니다.

  4. 수정 예시 만들기

    고치는 방법을 보여 주는 예시 코드를 만들고 컴퓨터 안에서 시험했습니다. 이것은 예시일 뿐이며 실제 서비스에는 적용되지 않았습니다.

수행한 작업

  • 정상 접속 방식(GET)으로 공개 화면과 직접 참조 프로그램 파일 수집
  • 저장한 응답, 안내문(헤더), 파일 지문(해시), 프로그램 코드 일부 분석
  • 가짜 데이터로 의심 구문을 컴퓨터 안에서 재현
  • 수정 예시 코드를 컴퓨터 안에서 시험

수행하지 않은 작업

  • 로그인, 실제 고객 정보 접근
  • 서버 공격, 침투, 부하 시험
  • 브라우저에서 실제 XSS(악성 코드 실행)나 인증 정보 전송 검증
  • 실제 서비스 코드 수정, 운영 배포, 서버 설정 점검

화면 쪽 개선 필요성은 확인되었지만 핵심 서버 통제는 확인 공백이 큽니다. 안전성 점수나 사고 확률을 계산할 근거가 부족합니다. 라이나에서 사고가 났다거나 대규모 유출이 가능하다는 것이 입증된 것은 아니지만, 현재 결과만으로 유사 사고가 불가능하다고 결론 내릴 수도 없습니다.

업무가 멈추지 않게 하는 확인

보안을 강화하다가 정상 업무가 막히지 않도록 로그인, 로그아웃, 본인확인, 전자서명, 청약, 제휴 화면, 캠페인 집계의 회귀 시험 범위를 정합니다. CSP 적용, 부품 교체, 쿠키 인증 전환은 연계 영향이 있어 단계적 적용과 되돌리기 계획이 필요합니다.

이번 점검에서는 응답 속도나 장애 복구 같은 안정성을 측정하지 않았습니다. HTTPS가 정상이고 화면이 열린다는 사실만으로 업무 연속성이 확인된 것은 아닙니다.

점검 범위와 한계

  • 이 보고서는 공식 홈페이지의 공개 화면에 대한 결과입니다. 라이나 전체의 안전성을 판단하지 않습니다.
  • 2026-10-28에 수집한 응답이 기준입니다. 그 이후의 변경은 반영되지 않았고, 이번 개정에서도 운영 사이트를 다시 점검하지 않았습니다.
  • 로그인, 실제 고객 정보 접근, 서버 공격, 부하 시험, 프로그램 설치는 하지 않았습니다.
  • 실제 침입, 로그인 정보 탈취, 고객정보 유출은 확인하지 못했습니다. 이것은 "없다"는 증명이 아닙니다.
  • 법령 준수 여부나 제재 책임은 이 기술 점검만으로 판단하지 않습니다. 침해사고 발생 여부를 판단하는 포렌식 보고서도 아닙니다.
  • 심각도 표현(높음·중간·낮음)은 고치는 순서를 정하기 위한 잠정 평가이며 점수(CVSS)나 침입 성공 판정이 아닙니다.

판정 표현을 읽는 방법

표현의미
확인수집한 응답, 코드 구문 또는 컴퓨터 안 시험에서 근거를 확보했다는 뜻입니다.
조건부 위험다른 조건이 함께 맞으면 피해로 이어질 수 있지만, 전체 경로는 입증하지 못했다는 뜻입니다.
미확인 · 확인 못함 · 미수행자료나 환경, 점검 범위의 한계로 판단하지 못했다는 뜻입니다. 안전하다는 뜻도, 결함이라는 뜻도 아닙니다.
수정 예시 코드고치는 방법을 보여 주는 예시입니다. 실제 서비스에 적용된 수정이 아닙니다.

용어 풀이

낯선 용어를 눌러 쉬운 설명을 볼 수 있습니다.

응답 헤더(보안 헤더)

웹사이트가 화면을 보낼 때 함께 붙이는 안내문입니다. 택배 상자에 붙은 "취급 주의" 스티커처럼, 브라우저에게 화면을 어떻게 다뤄야 하는지 알려 줍니다.

CSP (콘텐츠 보안 정책)

"이 사이트에서는 허용한 출처의 프로그램만 실행하세요"라고 정하는 규칙입니다. 허용 명단 밖의 프로그램이 끼어들어도 실행되지 않게 합니다.

X-Frame-Options · frame-ancestors

"이 화면을 다른 사이트 안에 끼워 넣지 마세요"라는 표지입니다. 클릭재킹을 막습니다.

클릭재킹

보이지 않는 투명 화면을 덮어씌워 방문자가 다른 버튼을 누르도록 속이는 수법입니다.

XSS (교차 사이트 스크립팅)

사이트 화면에 악성 코드가 끼어들어 방문자의 브라우저에서 실행되는 공격입니다. 화면에 들어가는 글이 걸러지지 않을 때 가능합니다.

토큰 (idToken · refreshToken)

로그인했다는 것을 증명하는 디지털 출입증입니다. idToken은 일상 출입용, refreshToken은 출입증을 다시 발급받는 데 쓰는 증표입니다.

API

화면과 서버가 데이터를 주고받는 창구입니다. 고객 정보 조회 같은 기능이 이 창구를 통해 이루어집니다.

라이브러리(부품) · jQuery · Axios

개발자가 직접 만들지 않고 가져다 쓰는 공용 프로그램 부품입니다. 오래된 부품에 공개된 약점이 있으면 그것을 쓰는 모든 사이트가 영향을 받을 수 있습니다.

CVE

공개된 보안 약점에 붙는 국제 식별 번호입니다. 예: CVE-2020-11022.

XSRF · CSRF

사용자가 모르는 사이에 다른 사이트가 사용자 이름으로 요청을 보내는 공격과, 이를 막는 확인 값입니다.

CORS

브라우저가 다른 사이트의 데이터 요청을 허용할지 정하는 규칙입니다.

출처(origin)

프로토콜(https), 도메인, 포트를 합친 주소의 정확한 단위입니다. 주소에 특정 글자가 들어 있는 것과 다릅니다.

HttpOnly · Secure · SameSite

쿠키의 보호 속성입니다. HttpOnly는 화면 스크립트가 읽지 못하게, Secure는 암호화 연결에서만 보내게, SameSite는 다른 사이트 요청에 붙지 않게 합니다.

HSTS

브라우저에게 "이 사이트는 항상 암호화 연결(HTTPS)로만 접속하라"고 기억시키는 설정입니다.

프로그램 묶음(번들) · JS

화면을 움직이는 프로그램 파일입니다. 누구나 내려받아 읽을 수 있는 공개 정보입니다.

innerHTML · v-html

글을 화면에 넣을 때 HTML 코드로 해석해서 넣는 방식입니다. 글자로만 넣는 방식과 달리 코드가 실행될 수 있습니다.

SBOM

소프트웨어에 어떤 부품이 어떤 버전으로 들어 있는지 적은 목록입니다. 약점이 발표됐을 때 영향 범위를 빨리 찾을 수 있습니다.

객체 권한

"이 요청자가 이 고객·문서·계약 정보를 볼 권한이 있는가"를 서버가 개별 데이터마다 검사하는 것입니다.

BFF · 서버 세션

로그인 증표를 브라우저가 아닌 서버가 보관하고, 브라우저에는 읽을 수 없는 출입 쿠키만 주는 구조입니다.

CDN · WAF

CDN은 화면을 가까운 곳에서 빨리 전달하는 배달망이고, WAF는 의심스러운 요청을 걸러내는 방화벽입니다.

로컬 재현 · 합성 데이터

실제 사이트가 아닌 내 컴퓨터 안에서, 진짜 정보가 아닌 가짜 값으로 코드를 실행해 보는 시험입니다.

회귀 시험

고친 뒤에 기존 기능이 여전히 잘 동작하는지 확인하는 시험입니다.

Report-Only (보고 전용 모드)

규칙을 강제로 적용하지 않고 위반 사항만 기록하는 시험 운영 방식입니다. 정상 기능이 막히는지 미리 알 수 있습니다.

근거 자료
