점검 방식(계획)
일반 방문자가 볼 수 있는 공개 정보만 읽기 전용으로 확인합니다. 로그인, 입력·제출, 프로그램 설치, 취약점 공격은 하지 않습니다.

결론

이 문서는 점검 결과가 아니라 점검 계획서입니다. 8개 사이트와 23개 주소는 아직 접속해 점검하지 못했습니다. 점검을 시작하기 전에 무엇을, 어떤 순서로, 어떤 기준으로 볼지와 결정이 필요한 사항을 정리했습니다.

대상

공식 홈페이지, 모바일 홈페이지, GA 업무지원, 전자구매, 다이렉트, 모바일 다이렉트, 공식 블로그, 다이렉트 공식 블로그 등 8개 사이트와 그 아래 세부 주소 23개입니다.

우선순위 (잠정)

높음 3건, 중간 14건, 낮음 6건입니다. 높음은 GA 멤버십 연동 테스트 화면, GA 설치 가이드 PDF, GA 업무지원 메인입니다. 우선순위는 점검 순서를 위한 제안이며 취약점의 심각도가 아닙니다.

왜 이 목록이 중요한가

대표 홈페이지(www)는 2026-10-28에 일부 점검했습니다. 최근 금융권 사고에서는 대표 홈페이지보다 업무·제휴·협력사 접점, 즉 "뒷문"이 문제가 된 사례가 있었습니다. 이 목록은 그런 접점과 과거 자료가 남은 경로를 포함합니다.

결정이 필요한 것

점검 범위 승인, 시스템별 운영 여부와 담당자 확인, 점검 수행 조건(접속 허용) 정리가 필요합니다. 아래 "결정이 필요한 사항"에 정리했습니다.

읽기 전에 목록의 "확인 내용"은 검색 결과와 화면 확인 기록이며 현재 서버 응답과 다를 수 있습니다. 종료된 이벤트나 과거 약관 페이지는 기록 보존용일 수 있어 방치된 시스템이라고 단정하지 않습니다. 미사용 여부는 운영부서 확인, 배포·폐기 이력, 접속 로그를 대조해야 확정할 수 있습니다.

23/23미점검23개 주소 모두 아직 접속해 점검하지 않았습니다

점검은 이렇게 진행합니다

쉽게 비유하면 건물 밖에서 하는 외관 점검입니다. 간판, 출입문 표지, 안내판을 확인하는 것이고, 문을 두드리거나 안으로 들어가지는 않습니다. 이번에는 건물이 8채, 출입문이 23개입니다.

  1. 접속 가능 여부 기록

    주소마다 현재 열리는지, 어디로 자동 이동하는지, 응답 상태(정상·찾을 수 없음·접근 제한 등)를 기록합니다.

  2. 보안 안내문과 사용 부품 확인

    응답에 붙은 보안 안내문(헤더), 쿠키 설정, 화면이 쓰는 공용 부품의 버전을 확인합니다.

  3. 화면 코드를 읽기 전용으로 관찰

    로그인 전에 보이는 정보, 시험용 문구, 내부 주소, 오래된 설치 안내가 남아 있는지 화면과 코드를 관찰합니다.

  4. 운영 부서와 대조

    발견한 경로가 지금도 필요한지, 담당자가 누구인지, 최근 접속 기록이 있는지 운영 부서 자료와 맞춰 봅니다.

점검 규칙

  • 요청은 읽기 전용(GET)만 보냅니다. 쿠키와 로그인 정보를 보내지 않고, 자동 이동도 따라가지 않습니다.
  • 주소 사이에 최소 1초 간격을 두고, 응답이 오류나 접속 제한이면 점검을 멈춥니다.
  • 사이트마다 요청 수와 응답 크기에 상한을 둡니다.
  • 내부망·로컬 주소는 접근하지 않습니다.

하지 않는 일

  • 로그인, 입력·제출, 본인인증 기능 실행
  • 설치 프로그램 내려받아 실행하거나 설치
  • 취약점 공격, 서버 침투, 부하 시험
  • 허가되지 않은 다른 도메인 점검

  6. 6과거 약관·서식20번 · 21번 · 22번 · 23번보존 목적과 최신 자료와의 연결을 확인합니다.

결정이 필요한 사항

각 결정은 "승인"과 "보류"의 의미가 다르므로 함께 적었습니다.

D-1

점검 범위 승인 (8개 사이트, 23개 주소)

권고 · 승인

위 목록을 읽기 전용으로 점검하는 것을 허가해 주십시오. 로그인, 입력, 설치, 공격은 하지 않으며, 점검 규칙은 "점검 방법"에 적었습니다.

승인하면

대표 홈페이지 밖의 업무·협력사·모바일·과거 자료 경로의 현황을 처음으로 파악할 수 있습니다.

보류하면

해당 시스템은 계속 점검되지 않은 채 남습니다.

D-2

시스템별 운영 여부와 담당자 확인

권고 · 승인

8개 사이트와 각 경로의 운영 부서를 지정하고, 최근 6~12개월 접속 기록과 배포·폐기 이력을 제공해 주십시오.

승인하면

"지금도 쓰는가"를 추측이 아니라 기록으로 판단할 수 있습니다.

보류하면

미사용 여부를 확정할 수 없어 정리 결정이 미뤄집니다.

D-3

점검 수행 조건 정리

권고 · 승인

점검을 수행할 환경(접속이 허용되는 곳), 점검 시간대, 이상 징후 시 연락할 담당자를 정해 주십시오. 이번 작업 환경에서는 8개 호스트 접속이 차단되어 있어, 접속을 허용하거나 접속 가능한 환경에서 수행해야 합니다.

승인하면

점검을 바로 시작할 수 있고 결과를 이 문서와 같은 형식의 결과 보고서로 정리합니다.

보류하면

점검이 시작되지 않습니다.

D-4

불필요한 경로의 처리 원칙

권고 · 승인

불필요하다고 판단된 경로는 다른 시스템과의 의존관계와 보존 의무를 확인한 뒤 접근 제한, 최신화, 제거 중에서 결정하는 원칙을 정해 주십시오. 검색 결과에서 숨기는 것만으로 접근 통제를 대신할 수 없습니다.

승인하면

정리 기준이 일관되게 적용됩니다.

보류하면

경로별로 판단 기준이 달라질 수 있습니다.

착수할 때 필요한 자료

  • 8개 사이트별 운영 부서와 담당자
  • 최근 6~12개월 접속 기록과 배포·폐기 이력
  • DNS·인증서 관리대장, WAF·CDN 서비스 목록 (목록에서 빠진 주소가 있는지 대조하기 위함)
  • 점검을 수행할 환경과 연락 채널
  • 비밀키, 실제 로그인 정보, 실고객 정보는 점검 자료에 포함하지 않습니다.

점검 범위와 한계

  • 이 문서는 점검 결과가 아닌 계획서입니다. 어떤 주소에 대해서도 취약 여부를 판단하지 않았습니다.
  • 목록은 검색 결과와 화면 확인을 바탕으로 정리한 것이며, lina.co.kr 아래 모든 호스트와 경로를 수집한 자산 목록이 아닙니다. 검색에 노출되지 않은 경로와 내부 전용 시스템은 빠져 있을 수 있습니다.
  • "확인 내용"은 목록 정리 당시의 기록입니다. 직접 화면 확인, 검색 확인, 이전 기록, 조회 실패를 구분해 적었으며 현재 서버 응답과 다를 수 있습니다.
  • 우선순위는 점검 순서를 위한 잠정 권고이며 취약점의 심각도 판정이 아닙니다.
  • 미사용 확정은 운영부서 확인, 배포·폐기 이력, 접속 로그의 대조가 필요합니다. 오래된 날짜나 경로 이름, 오류만으로 사용 종료를 확정하지 않습니다.
  • 공식 홈페이지(www)의 2026-10-28 점검 결과는 별도 보고서에 있으며 이 문서의 대상 목록과 일부만 겹칩니다.

용어 풀이

낯선 용어를 눌러 쉬운 설명을 볼 수 있습니다.

읽기 전용 점검(GET)

화면을 열어 보는 것과 같은 방식의 요청만 보내는 점검입니다. 데이터를 바꾸거나 입력을 보내지 않습니다.

응답 헤더(보안 헤더)

웹사이트가 화면을 보낼 때 함께 붙이는 안내문입니다. 브라우저에게 화면을 어떻게 다뤄야 하는지 알려 줍니다.

서브도메인

ga.lina.co.kr처럼 대표 주소 앞에 이름이 붙은 하위 주소입니다. 업무별로 따로 운영되는 경우가 많습니다.

GA

대리점(General Agency) 설계사 업무 지원 시스템으로 보이는 하위 사이트 이름입니다. 정확한 용도는 운영 부서 확인이 필요합니다.

보안 프로그램

웹 브라우저에서 로그인·전자서명 등을 안전하게 하려고 설치하는 프로그램입니다. 오래되면 그 자체가 약점이 될 수 있습니다.

SSO

한 번 로그인하면 여러 시스템을 다시 로그인하지 않고 쓰는 방식입니다.

IP 제한

허용된 주소에서 오는 접속만 받는 접근 통제입니다.

WAF · CDN

CDN은 화면을 가까운 곳에서 빨리 전달하는 배달망이고, WAF는 의심스러운 요청을 걸러내는 방화벽입니다.

자산 목록(관리대장)

운영 중인 주소와 시스템, 담당자를 적은 표입니다. 이것이 정확해야 빠진 접점이 없는지 확인할 수 있습니다.

우선순위(잠정)

점검할 순서를 정하기 위한 제안입니다. 위험이 크다는 뜻이 아닙니다.
